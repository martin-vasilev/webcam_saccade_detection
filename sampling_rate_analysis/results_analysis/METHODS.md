Exact candidate thresholds, units, IDT windows, event flags, minimum-duration arguments and conversion factors are in `data/frozen/part1/grid_definitions_source.csv`; that file is the authority rather than a hand-recreated grid. Sample-based windows and detector parameters retain their historical meanings, with whole-trial calls. Displayed Original/30-Hz grid points retain configuration-specific three-rate paired successful support inherited from Analysis B1; supports can change across thresholds. This is descriptive, exploratory cohort performance, not independent parameter selection.

I-HMM re-estimates states per trial/representation using its separate stochastic fitting mechanism and primary seed schedule 0. It has four preprocessing branches, not the classical threshold grid. CNN has five corrected branches: Raw, Mean3, Median3, SG3/7 and SG5/23. CNN branch scores are held-out estimates for those fixed branches, not a selected-branch estimate. The common SG5/23 panel uses its recorded historical descriptive thresholds, not necessarily the Phase 2B winner. Figure captions and denominator tables must accompany comparison.

## Part 2: training-only selection and held-out evaluation

For each outer held-out participant, representation and classical method, use only the other 19 participants. Candidates share preprocessing but can have event-specific fixation/saccade thresholds. First maximise jointly prediction-available eligible training rows. Among maximum-availability candidates, intersect their jointly successful training trials; score all tied candidates on identical training reference rows. Maximise J = (fixation MCC + saccade MCC)/2. Undefined MCC for either task makes a candidate inadmissible; no lower-availability fallback. J ties within 1e-12 follow Raw, Mean3, Median3, SG5/23 and ascending event-specific thresholds. I-HMM uses the four preprocessing candidates and its frozen primary seed, without threshold search. The byte-identical `selection.R` implements this; it is not executed during packaging.

Evaluate saved selected-policy held-out predictions on Original reference timestamps, never on interpolated nodes. The main review table uses `shared_preprocessing_joint` and `own_policy_paired_joint`: both event calls must succeed at both rates for each scored trial. Condition-specific and intersection-across-policy scores remain available separately. Different algorithms can retain different supports; their row SHA-256 identities and confusion counts are retained in full aggregate tables. An absent event is not assumed to mean a successful empty call. Prediction availability/failures remain distinct.

For binary classification with TP,TN,FP,FN: MCC = (TP TN − FP FN)/sqrt((TP+FP)(TP+FN)(TN+FP)(TN+FN)); F1 = 2TP/(2TP+FP+FN); precision = TP/(TP+FP); recall = TP/(TP+FN). A zero denominator gives undefined, not zero. Packaging reuses the original R metric functions and independently checks them in Python.

CNN five-branch scores use the established 68,577-row common Original reference support, 20 held-out participants per branch/rate. No branch selection is run. Raw remains the provisional common primary branch. The comparison table combines policy and fixed-branch estimands with explicit support labels, not a new unified selector or a ranking with common cross-method denominators.

## Part 2B: development-selected fixed settings

Eight classical method/representation choices use the same reliability-first joint criterion on the full development cohort. Their development scores are in-sample. LOPO frequencies indicate selection stability, not the rule used to choose the final setting. Exact settings and definitions are in `final_fixed_configurations.csv` and `selected_configuration_definitions.csv`. ## Part 3: native events and trial distributions

Native event intervals are preserved, not reconstructed from Original-timestamp binary scoring. Classical durations are end minus start; CNN durations are last minus first plus median sample step. A harmonised first-to-last-span sensitivity is kept separately. Native intervals are not silently split, interpolated or cropped at blocked gaps. Trial N, mean duration and sample duration SD are computed per successful call. A successful zero-event trial has N=0 and undefined mean/SD; a singleton has defined mean and undefined SD; failures have undefined measures. Event-pooled means/SD and equal-trial means of these trial statistics are separately labelled. The compact native summary and transport table use different supports; they must not be merged as though they describe the same trials.

Manual reference target-label runs use Original samples after confidence>0 and EyeLink pupil>0, sorted by actual timestamps. The historical literal R NA/cumsum implementation encounters 302 unknown labels in nine valid-input trials; its propagation can combine subsequent target runs under NA event IDs. This historical-compatible endpoint is retained, not silently repaired. The separate gap-aware sensitivity makes unknown labels boundaries and splits at frozen invalid/blink/75-ms blocked edges. The same Original reference events are used for both representations; no reference resampling/cropping is introduced.

Main transport compares equal-mass empirical trial vectors [N, mean duration, sample duration SD]. Reference means and sample SDs standardise all three dimensions; zero reference SD is replaced by one. Exact T4transport 0.1.8 W1 uses Euclidean ground distance. Record raw distances, univariate standardised distances and native-unit univariate differences, and similarity 1/(1+d). Historical `compute_wasserstein_full` uses method-specific paired complete cases and returns undefined for fewer than three trials. Harmonised common-complete support spans the four classical methods plus CNN Raw at both rates: historical 516 fixation and 366 saccade trials; gap-aware 518 and 367. Count-only common-success support, method-specific complete cases, native/span durations and branch-specific CNN supports/scales are separate sensitivities. These are comparisons of distributions of trial statistics, not paired-event detection accuracy. Existing exact-transport checkpoints are reused; no solver is run by this package.

Harmonised saccade speed uses raw coordinates from the native representation, actual timestamps, degrees/pixel x=0.01865554 and y=0.01919689, successive within-event differences, arithmetic mean and maximum speed. Derivatives across invalid/manual-blink/cap components are blocked; events missing required support remain undefined with reasons. Historical sensitivity retains each detector's preprocessing/derivative stencil. CNN speeds were already reconstructed without neural inference. Lower sampling can miss peak speeds. Velocity summaries report defined and undefined event counts and retain both velocity rules.

Original CNN had 78,492 input rows versus 73,796 classical/reference rows; 30 Hz had 40,791. Matched trial sets do not guarantee identical temporal exposure. Native event statistics, original-reference-time classification and frozen common-complete transport have different units/supports. The 124,837 reconstructed velocity records and 504 transport comparisons passed prior independent validation; archived evidence is provided, while this package performs aggregate reuse/identity checks only.

## Presentation and inference limits

Review CSVs contain source values, Markdown rounds to three decimals, and plots reuse exact saved numbers/curves. No parameter reselection, p-values, bootstrap draws, transport approximations or new scientific effect estimates are introduced. Temporal resampling with sample-based processing measures pipeline transfer rather than a causal hardware sampling-rate effect. The cohort informed historical Original settings. CNN 30-Hz Option A uses all available windows capped at 3,000 without replacement, with 1,000 epochs and fewer unique windows/updates than Original. Pooled MCC differences do not establish participant-level significance, equivalence or superiority.

## Executable scientific extension (26 November 2026)

The previous packaging-only version is preserved as historical evidence. The current R entry point now invokes original scientific modules through explicit R/Python input adapters. All-stage recomputation scores native events and held-out prediction rows, executes the original training-only and development selectors, reconstructs native/reference events and trial summaries, calculates velocities, and runs the pinned exact transport implementation. It does not redesign thresholds or choose a new CNN primary. Code extraction and environment-only adaptations are recorded in config/executable_code_manifest.json.

Computation scope is a runtime resource decision, not a new scientific endpoint: detector replay may be pilot/full/archived; exact transport may be a prespecified comparison subset or full. A subset always uses the original complete trial support, centring/scaling and solver. Full grid scoring and all native/reference/velocity computations are distinguished from representative detector/transport tests in validation/SCIENTIFIC_PIPELINE_VALIDATION.md. Every frozen scientific definition above remains unchanged.
