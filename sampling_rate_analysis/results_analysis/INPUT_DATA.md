# Scientific inputs and runtime boundary

Inputs remain outside this public candidate. **No participant data are bundled.** Set `--input-root` to an authorised copy of the frozen scientific workspace. `config/scientific_inputs.csv` gives the exact root-relative source path, artifact ID, source SHA-256 and permission status for every registered file. For data the runtime path is `input-root/source_relative`; four pure historical helper IDs have an explicit `runtime_location=package/...` and are bundled byte-for-byte; an organisation can therefore relocate the whole bundle without editing scientific code. The private run's `consumed_inputs.json` records the exact resolved local paths actually used. Do not publish that private provenance file without reviewing its paths and data references.

`config/input_schemas.json` records the exact CSV headers, including full names rather than guessed aliases. Input identity is byte-pinned; changed headers or changed data fail the hash gate. The downstream modules additionally check typed values, unique keys, fixed roster sizes, support identities, validity and interval rules. The current resolver validates the entire registered bundle even for a stage-specific command. Partial/smaller input bundles are not yet supported; missing files produce an artifact-specific error, never an aggregate fallback.

Every exact filename/column is in the machine-readable catalogs. Their source prefixes identify the corresponding Analysis A/B/C1/C3/downstream archive versions. Model weights and training windows are not required to score verified saved CNN predictions. Participant-held-out provenance relies on the frozen C3 production/validation gates and exported source identities; this Results pipeline does not retrain or newly certify the original training process.

## Validity, support and missingness

Original classical/reference input uses `conf > 0 & el_pupil > 0`; Original CNN native events retain their wider full-sequence exposure. The archived observed-frame 30-Hz input keeps actual timestamps and source IDs. Mean3/Median3 are sample-based; SG5/23 retains its historical short-input fallback. Whole-trial calls remain unchanged. Unknown manual labels are not filled. Historical R NA/cumsum segmentation and gap-aware unknown-breaking segmentation are computed separately. Invalid/blink/75-ms edges block the frozen derivative/reference-support operations; they do not silently resegment native detections. See METHODS.md and the scientific protocol JSONs.

## Availability and publication

The registered bundle was found locally and hash-checked during this task. That is not evidence that each derived participant-level file is publicly distributable. Public permission is recorded as not established. Obtain authorised copies through the team; do not assume downloading the GitHub repository supplies all corrected predictions, execution ledgers and source-anchor inputs. A missing or hash-mismatched input stops before calculation. `data/frozen/` is a comparison/reference and review input only; it cannot fill a missing scientific data source in recompute mode.

Scientific outputs include participant/trial/event information. `--output-root` must be an explicit private location outside the proposed release, historical scientific workspaces and manuscript. Do not add it to Git. Only reviewed aggregate validation/status evidence should be copied into the candidate package.

Inherited artifact IDs such as b_old_summary, h_old_summary and cnn_summary are provenance-only byte checks. They are not numerical inputs to scientific recomputation. The current complete-bundle resolver still checks their registered identities; the calculation consumers are mapped in ANALYSIS_FLOW.md. No final pooled table supplies a missing event/prediction calculation.
